# R26：每日随机时间自动签到

## 使用

「米游社功能」→「游戏每日签到」卡片新增自动签到开关及双滑块时间范围。

- 每个本地用户独立设置，默认关闭，默认范围为北京时间 **01:30～22:30**。
- 两个滑块以 **10 分钟**为一步，范围至少 10 分钟。拖动后点击「保存时间范围」，或切换开关一并保存。关闭时也可预先保存范围。
- 开启后，在范围内每天均匀随机抽取一个秒级时间点，发起本用户所有已添加米游社账号的原神、星穹铁道、绝区零国服签到。复用已有角色枚举、凭证检查和逐角色签到流程；已签到则跳过。
- 页面显示下次自动时间和最近结果摘要（成功／已签到／未完成数及错误原因），可以刷新查看。完整任务详情仍使用原有签到结果区；重启后保留摘要，完整详情不持久化。
- 无需保持网页打开或登录会话有效，服务端使用已保存的授权。服务器上的应用进程需要持续运行，不能仅靠 Nginx 或浏览器执行。

没有改变服务器配置、定时任务或系统时区。调度固定按北京时间 UTC+8 计算，不受 Debian／Docker 的本地时区影响。

## 每日计划及恢复

1. 保存启用状态后，如果当天还在范围内，从剩余范围选取时间；当天已过结束时间，则安排次日。每次普通保存不重新随机；修改范围或重新启用会重算尚未执行的计划。
2. 选出的具体时间保存在数据库中，重启或刷新网页不会重新抽取。当天执行后随机生成下一天的计划。
3. 自动任务每日最多启动一次。数据库先持久化当天执行标记，再入队，避免重启或重复调度再次启动；关闭再开启或当天修改范围不会增加次数。手动一键签到不受每日自动次数限制，仍先查官方状态。
4. 如果错过计划但恢复时仍在当天范围内，执行一次；已经超过范围，则标记跳过并安排后续计划，不在范围外补跑。如果停机跨过数天，只处理当前可执行日期，不连续补过去的日期。
5. 同一个用户已有手动／自动签到时，等待它结束后再检查是否仍可发起；不同用户复用原有队列。任务在共享队列中等到范围结束后仍未开始时直接跳过，不请求上游。范围约束任务开始时间，开始后的逐项处理可能延续到范围结束之后。
6. 关闭开关取消后续计划；属于自动签到的排队／运行任务会尝试停止，手动任务不受影响，已经完成的签到保留。
7. 服务中断时，已经领取执行标记但未记录完成的任务标为中断，当天不自动重试；可使用手动一键签到，按现有流程检查官方状态后处理。验证码、首次绑定、凭证失效等不会自动绕过或无限重试，页面显示相应原因。

日常运行最多每 30 秒检查持久化状态，临近随机时间使用更短的服务端计时器唤醒。进程调度、短暂数据库等待可能使启动时间略晚于计划；开始前仍检查当天时间范围，超出范围则跳过。

## API 与存储

用户会话隔离，写入继承现有 Origin、CSRF 校验；管理员会话不能代替普通用户修改该设置。子路径部署继续使用原有 API 前缀。

- `GET /api/community/checkin/automatic`：返回当前用户设置、下次计划、最近结果摘要。
- `POST /api/community/checkin/automatic`：提交以下 JSON，成功返回保存后的状态。

```json
{
  "enabled": true,
  "startMinute": 90,
  "endMinute": 1350
}
```

时间使用北京时间自当天零点起的分钟数。范围为 90～1350，两个端点相差至少 10 分钟且都位于从 90 开始的 10 分钟刻度；随机时间包含起点、不包含终点。

当前数据库的 `shared_snapshots` 使用 `auto-checkin:<本地用户ID>` 保存版本化设置、下次计划和最近摘要。查询仅处理仍存在的用户；比较并交换写入防止重复领取。兼容 SQLite 和 PostgreSQL，不增加数据库迁移、依赖或配置文件。没有在调度设置中复制 Token，签到时仍从现有凭证库读取并验证归属及版本。

仍按既有单实例部署模型运行；不引入外部 cron、队列服务或 Codex 自动化。Debian 原生启动和 Docker 只需更新构建并重启，之后由用户在页面开启；无需添加环境变量。

## 验证

两个定向测试文件共 14 项通过，包括默认关闭、时间范围与步长、随机计划持久化、用户隔离和接口权限、每日去重、日期边界、重启／错过范围、关闭与手动任务并行、原子领取、无需浏览器的计时器、停止调度以及共享队列超时；同时回归原有三游戏签到与祈愿链接流程。

前后端类型、构建及改动范围 lint 检查通过，保留既有统计图表分包体积提示。未使用真实米游社授权或签到，未运行扫码、浏览器、Docker 或真实 PostgreSQL 验证。
