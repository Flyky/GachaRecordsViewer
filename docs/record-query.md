# R09：记录查询 API 与页面

日期：2026-10-27（Asia/Shanghai）。登录后访问 `/records` 或导航中的「查询记录」。未登录时先到登录页，成功后返回查询页。

## 页面操作

选择当前 UID 后，页面默认显示全部已保存记录，时间倒序、每页 20 条。可组合筛选起止日期时间、卡池多选、角色／武器多选、3–5 星多选和名称子串，切换时间正序／倒序。不选择某类筛选即为全部，包含无法确定类型或星级的记录；选择具体类型或星级时排除该字段未知的记录。

时间输入表示当前游戏档案时区中的当地时间，起止时刻均包含在内，不按浏览器或服务器时区转换。最近一周／一月／三月以游戏时区当前时刻为终点；一周回溯 7 天，一月／三月按日历月回溯，并在目标月份天数不足时取最后一天。

编辑条件后点击「查询记录」生效，并回到第一页；页面会提示条件尚未应用，此时暂停旧结果的分页操作。重置恢复全部条件和倒序，保留当前每页条数。每页可选 20/50/100/200 条，提供上一页、下一页、页码跳转和匹配总量。切换 UID 会清空筛选并回到第一页、每页 20 条；当前档案数据版本改变时重新读取已应用的查询。

表格包含时间、物品名称、角色／武器、星级、原始卡池类型；名称按五星金色、四星紫色、三星蓝色显示，并保留文字星级。未知星级不染成三星，未知物品显示其 ID；元数据缺失或冲突有额外文字标记。悬停时间可查看原始记录 ID。

「显示总次数（按卡池组）」与「显示保底内次数」默认开启，可分别关闭；开关只影响展示，不重新查询或改变计数。窄屏表格在自身区域横向滚动，筛选与分页换行。

没有档案时提供数据管理入口，空档案和筛选无匹配记录分别显示空状态。请求中展示加载状态；非法时间、请求失败和档案不可访问有提示。用户或 UID 切换后旧请求返回的结果不会写回当前页面。

## 次数和名称规则

- 总次数是当前 UID、对应 UIGF 卡池组内全部已保存记录的累计序号，不是当前筛选或当前页的行号。原始池 `301/400` 共同使用 `301` 组，表格仍分别显示两个原始池名称；新手、常驻、武器活动、集录相互独立。
- 保底内次数是五星间隔，五星后的下一抽从 1 开始。完整历史先按 UTC 时间和无损数字 ID 正序计算，再筛选、倒序和分页。补入更早历史会重算。
- 第一段历史默认不完整，以 `≥ N` 展示已知记录内次数；未知或冲突星级导致无法判断五星重置时显示「不确定」。出现下一个已知五星后，从其下一条记录恢复确定计数。已知缺口使用领域逻辑的边界规则，本轮没有增加手动编辑完整性或缺口的功能。
- 查询以原始可选元数据重新解析；合法缺省字段可以用本地字典补全，明确无效的星级不能被字典静默补成确定星级。原始星级与字典冲突时也保持未知。本轮通过共享 `rawMetadataHints` 和领域元数据的 `untrustedFields` 保留此信息，导入与查询使用一致的规则。
- 按简体中文请求解析名称，同语言或未声明语言的来源名称优先；已声明其他语言且字典提供简体中文时可显示中文，未知物品保留来源名称。名称搜索同时匹配解析后的显示名称和原始来源名称，忽略字母大小写、去掉搜索词两端空格，按字面子串匹配 `%`、`_`、引号等字符，不使用正则或 SQL 通配符。

## API

`GET /api/profiles/:profileId/records`，仅允许普通用户会话。用户身份取自 Cookie，档案读取通过 R07 的 owner 条件与事务快照，不允许传入 owner ID。未知或属于其他用户的档案统一返回 404 `PROFILE_NOT_FOUND`。响应 `Cache-Control: no-store`，没有额外写操作。

| 查询参数 | 形式与默认值 |
| --- | --- |
| `from / to` | 可省略；`YYYY-MM-DD HH:mm:ss`，合法当地日期时间；允许单边范围，开始不能晚于结束 |
| `pools` | 逗号分隔 `100,200,301,302,500`，`301` 同时选择原始 `301/400`；省略或空字符串为全部 |
| `itemTypes` | 逗号分隔 `character,weapon`；省略或空字符串为全部 |
| `ranks` | 逗号分隔 `3,4,5`；省略或空字符串为全部 |
| `name` | 最多 512 字符；省略或空白为不限制 |
| `order` | `asc / desc`，默认 `desc`；同秒仍按十进制字符串 ID 稳定排序 |
| `page` | 1–100,000,000 的十进制正整数字符串，默认 `1`；超过最后一页时收敛至最后一页 |
| `pageSize` | `20 / 50 / 100 / 200`，默认 `20` |

筛选列表不接受未知值、重复值或额外空项；额外参数、非法格式和不支持的分页大小返回 400 `INVALID_REQUEST` 或 `INVALID_RECORD_QUERY`。日期不合法和颠倒区间返回 `INVALID_RECORD_QUERY`。没有匹配时返回 `page=1 / pageCount=0 / total=0 / records=[]`。

响应类型位于 `packages/contracts`：`RecordPageResponse` 包含当前档案 ID、UID、时区、完整已保存数量 `historyCount`、匹配数量 `total`、实际页码／每页数／总页数、当前页 `records`、完整历史的 `totalsByPool` 及 `metadataIncomplete` 标记。

每条记录显式投影 `id / itemId / time / name / itemType / rank / gachaType / pool / groupOrdinal / metadataStatus / pity`。`pool` 是用于计数的 UIGF 分组；`pity` 包含 `count`、`status` 和 `reasons`，未知星级时 count 为 null。没有原始文件、账号凭证、所有者或数据库内部字段。

当前实现每次从数据库读取当前用户和当前档案的完整快照，在服务端完成领域计算、字面筛选和分页，只将所需页传给浏览器。没有永久保存序号或筛选后保底值，也没有可能漏失回补历史的计数缓存。Schema 无变更。

## 本轮验证

21 项定向测试通过：SQLite 与真实 PostgreSQL 各执行三组相同 API 契约，覆盖组合条件、字面特殊字符、同秒长 ID、正倒序／分页拼接、空结果、页码收敛、非法请求、用户与档案隔离、游戏时区边界、未知／冲突星级以及历史回补；同时重跑受本轮元数据适配影响的 9 项领域测试和 6 项 UIGF 编解码测试。没有重跑其他旧后端测试。

受影响包类型检查、零警告 lint、后端及依赖构建、前端构建通过。使用合成账号和临时 SQLite，在本机 Edge 完成一轮核心浏览器流程：筛选应用重置页码、卡池多选、字面名称、日期快捷项、正序、翻页／跳页、独立次数列、星级颜色、空结果、UID／账号切换、迟到查询结果丢弃，以及 390px 页面无整体横向溢出、无页面脚本异常。已检查桌面与手机版截图。

临时服务和独立 PostgreSQL 均在验证后关闭。脚本、截图和合成运行数据只在忽略目录中，没有读取或导入真实用户 JSON。本轮没有接入统计页面，下一轮 R10 实现分析计算与接口。
