# R19：临时 API 模拟

2026-10-28

## 使用

数据管理页底部新增「API 模拟」卡片。选择游戏账号（原神 UID）与输出格式，点击「生成 API」，再使用「复制 URL」提供给接收应用。复制失败时可以选中 URL 手动复制。

- 默认选择当前档案、祈愿链接格式；可切换米游社或 UIGF v4.0。
- 每次创建固定保存该 UID 当时的全部卡池记录快照，不受查询页筛选影响，不截取最近记录、不限制返回条数。后续导入或刷新不改变已创建的快照，需要重新生成。
- 每个本地账号同时保留一个接口，重新生成成功后原链接立即失效。生成失败保留原接口。
- 最长有效 15 分钟，页面显示倒计时和到期时间。读取链接、刷新状态、离开页面或退出登录都不续期。「销毁 API」立即撤销当前接口，也会取消正在生成的接口。
- 返回页面会恢复服务端当前有效接口；到期自动释放快照，服务重启后全部失效。无需新增配置、数据库表或迁移，SQLite／PostgreSQL 共用已有账号隔离导出逻辑。
- URL 本身就是这份快照的临时读取权限，接收应用无需本站登录。链接不含真实 AuthKey、米游社 Token、Cookie 或本地会话，只包含随机临时访问密钥。请提供给可信的接收方。

## 格式与兼容范围

### 祈愿链接／米游社

已有 provider 的「游戏链接导入」与「米游社授权刷新」均访问官方 `getGachaLog` 获取祈愿记录；米游社授权的区别在于先换取 AuthKey，并不存在本项目已使用的另一种独立抽卡结果格式。因此保留两个格式选项，当前输出相同的 `retcode / message / data.list` 结构。字段及字符串 ID 参考 [getGachaLog 响应样例](https://github.com/jvergerolle/Genshin-Impact-Wish-history-API#returned-json-example)，具体名称补全沿用本项目字典与原始元数据规则。

```json
{
  "retcode": 0,
  "message": "OK",
  "data": {
    "page": "1",
    "size": "1",
    "total": "1",
    "region_time_zone": 8,
    "list": [{
      "uid": "123456789",
      "id": "9007199254740993001",
      "item_id": "11301",
      "gacha_type": "301",
      "time": "2026-10-27 12:00:00",
      "name": "冷刃",
      "item_type": "武器",
      "rank_type": "3",
      "count": "1",
      "lang": "zh-cn"
    }]
  }
}
```

- ID 按十进制字符串保存并倒序输出，保留原始卡池代码（包括 `400`）、服务器本地记录时间及 UTC 时区偏移。
- 第一次请求返回所有卡池记录，忽略 `size`、`gacha_type`、`lang` 等筛选或分页大小参数，不翻译已保存的记录名称。
- 为防止接收方不断重复拉取，`page > 1` 或非零 `end_id` 返回 `data.list: []` 作为结束标记；这里不对数据切片。`page` 必须为正整数字符串，`end_id` 必须为非负十进制字符串。
- 生成 URL 是本站地址，包含模拟的 `authkey`、`auth_appid=webview_gacha`、`authkey_ver=1`、`sign_type=2`，不是官方祈愿凭证。仅能供支持自定义接口地址和整批结果的应用使用。硬编码官方域名、将 URL 重写到官方服务器、强制检查每页条数或逐池校验的导入器可能不兼容；无法通过响应格式解决这些限制。
- 本应用现有「祈愿链接导入」仅接受官方域名，继续保持这一限制；本轮未将它改成任意地址抓取。

### UIGF

复用现有 UIGF v4.0 导出器，返回 `info` 和只含该 UID 的 `hk4e` 数组，字段类型遵循 [UIGF 标准](https://uigf.org/en/standards/uigf.html)。原神常规记录沿用项目默认 v4.0；本轮不增加版本选择，也不增加星铁、绝区零或千星奇域记录输出。

UIGF 输出仍保留原始可选元数据的现有导出规则，不为了模拟 API 改写历史记录。请求参数不裁剪 UIGF 文档。

## 接口

以下路径相对应用根目录，部署在 `/gacha/` 时均带 `/gacha` 前缀。复制 URL 使用配置中的 `publicUrl`，须设置为外部可访问的域名与正确子路径。

| 接口 | 权限／输入 | 结果 |
| --- | --- | --- |
| `GET /api/mock` | 本地用户登录 | `{ link, serverTime }`，没有有效接口时 `link: null` |
| `POST /api/mock` | 用户登录、Origin、CSRF；`{ profileId, format? }` | 201，生成／替换本人接口；格式为 `wish-link`（默认）、`miyoushe`、`uigf` |
| `POST /api/mock/destroy` | 用户登录、Origin、CSRF；`{}` | 销毁本人当前接口，返回 `link: null` |
| `GET /api/mock/getGachaLog?authkey=...` | 持有随机链接，无需登录 | JSON 快照；失效或不存在统一为 404、`retcode: -100` |

管理结果中的 `link` 包含 ID、profileId、UID、格式、记录总数、创建与到期时间（毫秒）、URL。格式和档案绑定在创建结果上，不能通过更改公开 URL 参数切换到另一份数据。

链接使用 32 字节随机密钥，查询时按摘要查找；不进入数据库、配置、前端持久存储或应用请求日志。公开 GET 支持跨域只读访问，响应禁止缓存、搜索引擎索引和 Referer 传播。Nginx 等外部代理仍可能记录完整查询参数；若需要记录访问日志，建议对此接口使用不包含 `$args`／`$request` 的日志格式，或在该路径关闭访问日志。

进程总计最多保留 128 份有效快照、128 MiB 序列化数据，超出返回 `MOCK_CAPACITY`，不限制已导入的账号或数据库记录。生成期间同一用户的并发创建返回 `MOCK_BUSY`，销毁和停服会阻止未完成的创建重新发布链接。

## 本轮验证

使用独立临时 SQLite 数据与合成 UID，4 项定向测试覆盖登录／Origin／CSRF／归属、三格式、全部卡池、长 ID、空列表结束标记、子路径、跨域响应、替换与销毁、到期边界／自动定时清理、不续期、固定快照及跨服务实例失效。未使用真实米游社凭证，未请求官方个人数据，未运行扫码、浏览器或真实 PostgreSQL 验证。
