2. 两份 Compose 配置解析通过；PostgreSQL 空密码样例应拒绝解析。构建网络首次 Docker Hub 超时，使用本机已有代理的进程环境重试后成功，没有修改系统代理或镜像源。
3. 实际导出构建上下文并检查 345 个条目，必需源码／迁移在内，本地 data、配置、密钥、真实 JSON、node_modules、测试结果均不在上下文。运行数据未提交 Git，也没有 COPY 到镜像中。
4. 新增 2 组定向契约（SQLite／真实 PostgreSQL 18.4）：干净部署、管理创建／重置、旧结构升级、配置冷备恢复、管理员／会话／用户／记录／Token 保留，以及记录／分析／三版本导出和 owner 隔离。server 类型、定向 lint 通过；没有重跑无关全量。

## 支持边界

本机 Windows 原生 Node 与 Docker Linux amd64 的两种数据库均有实际结果；其他 CPU 架构、用户远端服务器、域名／证书和防火墙需在目标环境确认。Caddy 配置是部署示例，未发布到实际域名。

直接授权先支持国服官服；渠道服只确认角色列表，在线记录未实测，国际服需要独立 provider。上游窗口之外的历史通过 UIGF 合并，不承诺恢复已不可查询记录。约 8 位用户是预估规模，没有实现账号总数硬限制。

数据库模式切换不自动搬迁；主密钥轮换、跨实例扫码／任务接力与分布式部署不提供。变更 PostgreSQL 主版本或回退已升级结构需要单独恢复流程。

R13／R14 的独立 LToken-only／Cookie Token-only 真实输入已在上述参考验证中补充；用户自己的账号、Debian 主机、域名和网络仍由用户后续自行确认。本轮没有因文档整理再启动新的功能测试或扫码。
