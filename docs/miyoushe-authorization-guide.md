# 米游社授权与凭证获取手册

更新日期：2026-10-27

用途：对应已实现的 `/help/miyoushe` 帮助页与 `/accounts` 米游社页面。R13／R14 已实测国服官服扫码、重新授权、加密保存与当前窗口刷新；外部工具步骤依据前期文档和源码核对，未以真实账号操作验证。页面使用与验证范围见 [R15 页面说明](community-pages.md)。

## 1. 先选择你需要的方式

| 目标 | 建议方式 |
| --- | --- |
| 只导入、查看和备份历史记录 | 直接使用 UIGF 文件，不需要米游社授权 |
| 在本应用内刷新国服原神记录 | 优先使用本应用内置米游社 App 扫码 |
| 内置扫码不可用，但能从其他工具取得 SToken | 使用手动 Token / Cookie 导入 |
| 只有普通网页登录 Cookie | 可以验证其身份能力，但可能无法刷新祈愿；需补充 SToken |
| 不希望在服务器保存长期凭证 | 首版使用 UIGF；下一版增加已确认的祈愿链接导入 |

本地应用账号的用户名 / 密码只用于登录本 Web App。它与米游社、游戏账号完全独立。所有凭证只应导入你信任的本应用部署，不要发送到群聊、公开反馈或 GitHub Issue。

## 2. 首选：在本应用内扫码绑定

适用范围：已实测的国服官服原神账号；渠道服角色列表可取得，但刷新仍未实测，国际服尚未适配直接授权。其他历史可通过 UIGF 导入。

1. 先用管理员给你的本地账号登录。
2. 打开“米游社账号”，选择“扫码添加账号 → 生成二维码”。
3. 手机打开官方米游社 App，确认当前登录的是要绑定的账号。
4. 使用官方 App 扫描网页显示的二维码，在手机上核对并确认授权。
5. 网页显示“等待扫描 → 等待确认 → 正在验证授权”。超时或取消后重新生成二维码。
6. 授权成功后，网页列出获取到的游戏角色与 UID，选择要管理的原神档案。
7. 点击“开始刷新记录”，等待分卡池拉取完成，查看新增数、重复数或失败原因。

扫码流程不要求你把米游社密码填入本应用。二维码由本应用服务端向上游创建，结果回到本应用当前登录会话；不要扫描来历不明的账号绑定二维码。

若页面仅显示“身份已验证，祈愿刷新不可用”，说明尚未取得或验证所需 SToken；不能把它当作完整授权成功。

## 3. 备用：从 TeyvatGuide 获取包含 SToken 的 Cookie

适合 Windows / macOS 用户。TeyvatGuide 调查时仍维护扫码、验证码和 Cookie 登录，也提供“复制 Cookie”按钮。以下菜单名称依据当前源码，外部应用版本更新后可能调整。

1. 从 [TeyvatGuide 项目主页](https://github.com/BTMuli/TeyvatGuide)进入其发布或下载渠道。Windows 可使用项目链接的微软商店版本，macOS 可使用项目 Release。
2. 打开工具设置页，找到账号登录区域。
3. 使用工具提供的扫码或验证码登录完成本人米游社授权；遇到官方验证时正常完成验证。
4. 在用户信息卡 / Badge 中找到标题为“复制 Cookie”的按钮。
5. 将复制内容粘贴到本应用“米游社账号 → 手动导入凭证”的输入框。
6. 点击“验证并保存凭证”，核对返回的米游社身份，再选择对应的原神 UID。
7. 确认已校验 SToken 且 UID 可选后进行刷新；实际拉取还会校验上游角色与临时授权，不要以“Cookie 文本可以解析”替代能力验证。

常见完整字段示意如下，所有值均为占位符：

```text
stuid=<米游社账号ID>; stoken=<实际SToken>; mid=<实际mid>;
```

也可能同时包含 `ltuid`、`ltoken`、`account_id`、`cookie_token` 或 v2 命名字段。直接粘贴本人导出的完整内容，由应用识别实际版本；不要把其他账号的字段混在一起，也不要凭空改字段名。

如果导出结果不含 SToken，回到外部工具检查登录方式及当前凭证能力，不要把 LToken 的值改名为 SToken。

步骤依据：[TeyvatGuide 说明](https://github.com/BTMuli/TeyvatGuide/blob/72c3f371673e40cf0c2153535ddddafd24462fbc/README.md)、[复制 Cookie 按钮实现](https://github.com/BTMuli/TeyvatGuide/blob/72c3f371673e40cf0c2153535ddddafd24462fbc/src/components/pageConfig/tc-userBadge.vue)、[扫码取得 SToken 的实现](https://github.com/BTMuli/TeyvatGuide/blob/72c3f371673e40cf0c2153535ddddafd24462fbc/src/components/pageConfig/tco-gameLogin.vue)。

## 4. 高级备用：手动读取本人网页登录 Cookie

这条方法可以取得浏览器当前已有的 Cookie，**不保证能取得 SToken**。它适合已有网页登录态的导入与诊断，不能作为自动刷新祈愿的保证步骤。

1. 在本人浏览器打开[米游社官网](https://www.miyoushe.com/)，通过官方页面登录。
2. 打开浏览器开发者工具，在“应用 / Application → Cookie”中查看米游社相关域名下的字段。
3. 如果页面业务请求已携带 Cookie，也可在“网络 / Network → 对应官方请求 → 请求标头 / Request Headers”中查看实际发送的 Cookie。
4. 只复制属于该米游社账号的必要字段；不要导出整个浏览器、其他网站 Cookie 或完整 HAR 文件。
5. 在本应用手动导入页粘贴，执行验证并查看能力状态。
6. 如果只有 `ltoken/ltuid` 或对应 v2 字段，没有 SToken，改用前两节方法。

不提供“在控制台执行 `document.cookie` 就一定取得所有凭证”的教程：HttpOnly 字段不可由网页脚本读取，某些凭证也根本不在普通网页登录态中。正常浏览器还不会允许本应用直接读取米游社站点 Cookie。

## 5. 没有长期凭证时：UIGF 迁移

1. 使用你已有的抽卡记录工具导出其支持的 UIGF v4.0 / v4.1 / v4.2 文件。
2. 在本应用“数据管理 → 导入 UIGF”中选择该文件。
3. 核对文件识别出的原神 UID、时区和记录范围，选择要导入的档案。
4. 确认预览中的新增 / 重复 / 跳过信息，再执行导入。
5. 完成后在查询和统计页核对记录，并定期导出新的 UIGF 备份。

文件含星铁、绝区零或千星奇域时，首期只处理原神 `hk4e`；页面会提示其他数据未导入。旧内部 `result/typeMap` JSON 不属于支持的 UIGF 格式，旧格式导入和历史转换均不提供；需要使用工具导出的合法 UIGF 文件，不能只改扩展名或版本号。

## 6. 下一版：祈愿链接导入

该功能已确认需要实现，安排下一版。当前帮助页说明其尚未开放，不展示提交入口；以下为实现后的操作说明草案。

1. 在官方游戏内打开祈愿历史记录。
2. 使用你信任的现行工具从本机日志 / 缓存等位置取得该页面的祈愿链接。
3. 在本应用“通过祈愿链接获取”入口提交链接。
4. 应用提取临时 AuthKey，验证返回 UID 与所选档案一致后拉取记录。

纯网页部署无法替你读取游戏电脑的本地日志与缓存；服务器在另一台机器时尤其如此。链接会失效，需要重新取得；不承诺固定有效小时数。该方式不自动得到 SToken 或 LToken，也不会因此具备签到和战绩能力。

## 7. 在本应用查看与更换 Token

- 打开本人米游社账号详情，默认看到遮挡的字段、存在状态及最近验证状态。
- 本人主动点击对应“查看 / 复制”后才读取该项明文；当前使用现有本地登录会话，不额外要求输入密码。查看后最多 60 秒、窗口失焦或离开页面会隐藏，明文不写入浏览器存储。
- 显示“未取得”的字段没有对应凭证；应用不会生成占位 Token 作为成功结果。
- 需要更新时选择“重新授权”或“更新凭证”；应验证成功后替换旧凭证，避免一次失败输入覆盖可用授权。
- 选择“解除绑定”会删除本应用保存的该账号凭证，默认保留抽卡历史。若需要撤销上游登录，请按官方账号中心提供的会话 / 设备管理方式处理；本地解绑不等于上游已撤销。

普通管理员页面不提供查看其他用户 Token 的功能。自建服务器运行者掌握服务、数据库和密钥，使用共享部署前应理解这一信任关系。

## 8. 常见问题

| 现象 | 含义与处理 |
| --- | --- |
| 二维码超时 / 用户取消 | 重新生成；离开页面会尝试取消，临时票据仍受约 3 分钟有效期限制 |
| 能登录米游社，但无法刷新祈愿 | 检查是否取得有效 SToken，不能把普通网页 Cookie 当作完整授权 |
| 授权账号有误 | 停止绑定，手机切换正确账号后重新扫码 |
| 没有目标 UID | 检查服务器 / 渠道与米游社绑定关系，不手工伪造归属 |
| 需要设备或人机验证 | 按官方提示处理；如本应用尚未适配，改用外部工具获取凭证或 UIGF |
| AuthKey 失效 | 首版使用有效长期授权重新生成或重新授权；下一版链接导入可通过重新取得链接恢复 |
| 昨天的记录有、刚抽的没有 | 等上游历史记录更新后再刷新 |
| 刷新只取得近一段时间 | 上游历史查询窗口有限；此前备份的历史需要从 UIGF 合并 |
| 重复导入已有记录 | 应显示重复数而不重复增加；无需先清空历史 |
| 国际服或渠道服失败 | 参照该 provider 的适配状态，不套用国服官服说明；可先用 UIGF |

## 9. 不采用的旧教程

不要依赖“网页登录票据一定能换 SToken”或旧 GameToken 扫码脚本。旧资料虽仍可访问，但相关行为已变化；本轮已找到维护者失效反馈。帮助页不应继续发布这些脚本的一键成功教程。
