## 页面

- 删除「米游社功能 → 游戏每日签到」中的「管理米游社账号」按钮。
- 在统计分析的物品分组与年月统计之间加入「欧非分析」，使用当前 UID 全部保存记录，不受查询页筛选、物品角色／武器切换或 Daily 年份／卡池选择影响。
- 分别显示角色 UP（301／400 合并）、武器（302）、常驻（200）、集录（500）的五星平均抽数、样本数和总抽数。
- 角色 UP 显示小保底不歪率、UP 五星平均获取抽数、最多连续歪和最多连续不歪。空样本显示「—」，不把缺少样本显示成 0% 或 0 抽。

## 统计口径

| 指标 | 计算方法 |
| --- | --- |
| 五星平均抽数 | 可确认完整的五星间隔之和 ÷ 完整间隔个数。包含五星所在的那一抽，排除首段起点未知、已知缺口、未知／矛盾星级和末尾尚未出金的抽数。起点有明确证据时可包含首次五星。 |
| 总抽数 ÷ 五星数 | 作为另列参考值，包含已保存首段和末尾未出金的抽数；不与完整间隔均值混为同一指标。 |
| 小保底不歪率 | 可确认抽取前为小保底的五星中，当期 UP 数 ÷ 可判定小保底样本数。大保底命中不进入分子或分母。首次大小保底状态未知时，无论其结果为 UP 还是歪，都排除该次。 |
| UP 五星平均获取抽数 | 上一个可确认 UP 之后至本次 UP 的全部角色池抽数之和 ÷ 完整获取周期个数，中间歪到的五星成本也累计。首次起点未知或跨越未知记录时排除对应周期。 |
| 最多连续歪／不歪 | 按时间与记录 ID 排序后的小保底结果连续长度。大保底不参与计数，也不打断连续歪；未知样本或已知缺口会中断。 |

这是已保存历史的描述统计，不推导下一次中奖概率，不推断捕获明光隐藏状态；捕获明光产生的 UP 也作为本次小保底实际不歪计入。只有已导入的数据可以参与，未声明的历史遗漏无法自动发现；最多连续次数代表可确认的已保存片段。

### 大小保底状态

- 初始状态未知，不能仅看到首次歪就把它补进小保底分母，否则会造成选择偏差。
- 一次已识别的 UP 之后按小保底处理；非当期 UP 五星之后按大保底处理。
- 大保底状态下再次出现非 UP，标为状态矛盾，不计入小保底结果，并中断成本和连续次数；后续从新的可确认结果继续建立状态。
- 未知星级、同物品 ID 的矛盾星级、已声明的缺口，以及无法匹配历史卡池的五星均不能悄悄当作完整记录处理。

## 历史 UP 数据

UIGF 与已使用的官方祈愿记录没有提供「该条是否 UP」标志。物品字典也不包含某期 UP 名单。这里使用 [paimon-moe 历史角色祈愿数据](https://github.com/MadeBaruna/paimon-moe/blob/105d0ebd1d551de96668b805d88c2c9a0590177a/src/data/banners.js) 的时间范围与 UP 角色，匹配到项目物品 ID；换算方式参考同仓库的 [wish.js](https://github.com/MadeBaruna/paimon-moe/blob/105d0ebd1d551de96668b805d88c2c9a0590177a/src/functions/wish.js)。

- 本轮内置 107 个角色祈愿时间段，从 2020-09-28 至来源中的 2026-11-03；同时 UP 的角色按来源的名单合并。
- 按物品 ID 与时间判断，能够区分刻晴、提纳里、迪希雅、瑞希自身 UP 期间与其他期间；不靠名称或固定常驻角色黑名单猜测。
- 数据来源以亚洲时间为基准。同步开始／结束的时间按来源标志换算到各服务器；按服务器本地时间开始的阶段保持本地时刻。没有对应时间段的记录标为未知；边界依赖社区源准确性。
- R20 的卡池快照、版本、来源 SHA256 与 MIT 许可随代码保存。R21 新增管理员独立刷新与数据库缓存，见 [R21](r21-banners-topup.md)。字典刷新不会自动刷新历史卡池；角色名称字典与历史 UP 名单是两份不同的数据。
- 将来补充卡池数据时，运行 `pnpm --filter @gacha/gacha-core update:banners`，检查差异后随代码提交与部署。若源中角色无法映射到已内置物品 ID，脚本会要求先更新物品字典，不把遗漏当成歪。
- 更新脚本只使用 TypeScript AST 读取字面量字段，不执行下载的 JavaScript。仅在成功解析、映射与检查后写入快照；脚本使用的源 revision 固定到此次获取的提交，MIT 声明保存在 `packages/gacha-core/BANNERS_LICENSE`。

## 接口与一致性

新增 `GET /api/profiles/:profileId/analysis/luck`，仅登录用户可读取本人档案，查询参数为空。和其他分析接口一致返回 profileId、UID、时区、dataVersion、dictionaryVersion、historyCount 与元数据问题数量，另含 `pools`、`character`、`bannerSource`。

前端将欧非结果加入原有的版本一致性检查；数据／字典版本或历史条数不同则整体重试一次，避免混用导入前后的统计。空样本在 JSON 中为 `null`。不修改数据库、原始抽卡记录或导出结果，不新增依赖和迁移。
