# R18：多游戏签到与祈愿链接导入

日期：2026-10-28（Asia/Shanghai）。本轮为 R17 后续扩展，不改写 R01–R16 的原始范围；不新增配置文件或数据库迁移。

## 可行性调查

三款国服游戏均有可参考的角色发现、签到状态与签到提交实现。主要依据为 [TeyvatGuide 的 lunaReq.ts](https://github.com/BTMuli/TeyvatGuide/blob/72c3f371673e40cf0c2153535ddddafd24462fbc/src/request/lunaReq.ts) 和 [请求头实现](https://github.com/BTMuli/TeyvatGuide/blob/72c3f371673e40cf0c2153535ddddafd24462fbc/src/utils/network/getRequestHeader.ts)，并与 [MihoyoBBSTools 的游戏签到实现](https://github.com/Womsxd/MihoyoBBSTools/blob/f062d1fda8fab88fd312a5ca3a89537f6351943b/gamecheckin.py)／[活动配置](https://github.com/Womsxd/MihoyoBBSTools/blob/f062d1fda8fab88fd312a5ca3a89537f6351943b/setting.py)交叉核对。它们是社区实现，不能把源码存在视为当前账号已经签到成功。

本应用采用与既有 provider 一致的 2.115.0 协议，三游戏分别调用固定的 `api-takumi.mihoyo.com/event/luna/{game}/info`、`/sign`；POST 使用 X6 DS、角色 UID、region 和对应活动 ID。既有 SToken 可换取 Cookie Token；只有 LToken 的账号暂不能发现完整角色并签到。不会调用第三方验证码服务或尝试绕过官方验证。

祈愿链接可作为短期 AuthKey 来源，不需要保存长期社区 Token。获取方法参考 [genshin-wish-export 的缓存定位](https://github.com/biuuu/genshin-wish-export/blob/c4675ab9c359ce87cd9987d4bd0c5b2ea84a7e0c/src/main/getData.js)及[缓存目录规则](https://github.com/biuuu/genshin-wish-export/blob/c4675ab9c359ce87cd9987d4bd0c5b2ea84a7e0c/src/main/utils.js)。本轮独立编写可下载的 PowerShell 脚本，不执行远程下载代码、不设置代理或安装证书。

## 一键游戏签到

在侧边栏“米游社账号”下新增“米游社功能”，路径 `/miyoushe`，子路径部署如 `/gacha/miyoushe`。

1. 先在“米游社账号”添加本人的账号，可添加多个。
2. 打开“米游社功能”，点击“一键签到全部账号”。进入页面、刷新状态和启动服务均不会自动签到。
3. 扫描当前本地用户保存的所有米游社账号，发现其原神、星穹铁道、绝区零国服角色；同一账号多个 UID／服务器分别处理，不受当前侧栏档案限制，不处理其他本地用户的账号。
4. 每个角色先查官方状态；已签到则跳过，否则提交一次并再次检查。POST 超时／连接中断时只查一次结果，不盲目重复提交；下次执行仍先查状态。
5. 逐项显示成功、已签到、无角色、缺少凭证、授权失效、首次绑定和安全验证等结果。个别角色失败可继续处理其他角色；安全验证需要用户在官方 App 处理。

支持后台逐项进度、取消和再次查看状态。取消不撤销已完成的签到；解绑或替换凭证后不再用旧凭证发起后续操作。没有定时签到、补签或 HoYoLAB 国际服签到入口；也没有新增星铁／绝区零的抽卡、角色或副本页面。

| 接口 | 请求 | 结果 |
| --- | --- | --- |
| `POST /api/community/checkin/jobs` | `{}` | 202，创建本人的批次 |
| `GET /api/community/checkin/job` | 无 | 本人最近一次任务或 null |
| `POST /api/community/checkin/job/cancel` | `{}` | 取消本人当前批次 |

这些接口需要普通用户会话；写请求校验 Origin、JSON 和 CSRF。管理员会话不能代替普通用户身份。

## 祈愿链接导入／合并

入口为“数据管理”的“祈愿链接导入”，支持原神五类卡池，千星奇域及星铁／绝区零抽卡不纳入本轮。

1. 在运行游戏的 Windows 电脑打开原神祈愿历史，等待列表加载。
2. 页面展开“如何获取祈愿链接”，下载 `get-wish-link.ps1`，可以先查看源码，再按页面命令在本地执行。自动定位失败时用 `-GameDataPath` 指定 YuanShen_Data 或 GenshinImpact_Data 目录。
3. 脚本从游戏日志定位安装目录，再读取最近的 Chromium webCaches／Cache_Data/data_2；支持带版本号和不带版本号的缓存目录。只读文件、复制结果到剪贴板并输出链接，不上传本地文件，不修改游戏。游戏更新改变缓存格式时可能需要更新脚本；无法读取时仍可使用已有工具“复制祈愿链接”、UIGF 导入或米游社刷新。
4. 将完整链接粘贴到页面，选择实际服务器后“导入并合并记录”。国服官服／渠道服为 UTC+8，美服 -5、欧服 +1、亚服／台港澳 +8；选择不一致且已有档案服务器／时区冲突时会拒绝合并。
5. UID 从官方返回的记录取得，各页和各池必须一致；在当前用户下找到或新建该 UID 的档案。无需绑定社区账号。按页复用已有 UIGF 去重／补全／冲突规则，保留上游窗口外的历史，不自动宣称完整历史。

服务端不会访问粘贴的任意 URL：只接受允许的官方来源域名与原神 webview_gacha 参数，提取 AuthKey 后重建固定国服／国际服官方 API 请求；不传递其他查询参数、Cookie 或浏览器头。不接受其他游戏、重复关键参数、非 HTTPS、自定义端口或任意代理目标。

链接只在任务运行内存中保留，不写入配置、数据库、浏览器存储、公共响应或日志；任务结束／取消／停止后释放引用。任务创建成功后清空输入，离开页面也清除未提交输入。AuthKey 过期需重新获取，不承诺固定有效期。

| 接口 | 请求 | 结果 |
| --- | --- | --- |
| `POST /api/wish-link/jobs` | `{ "url": "完整链接", "region": "cn_gf01" }` | 202，创建本人导入任务 |
| `GET /api/wish-link/job` | 无 | 本人最近一次任务或 null，含逐池进度与新增／重复／补全计数 |
| `POST /api/wish-link/job/cancel` | `{}` | 取消本人任务，迟到页不能继续写入 |

逐页最多 20 条，按 end_id 前进，检查 UID、记录 ID、卡池和时间；空物品 ID 使用当前字典反查。无法识别物品或该池错误时保留已写入页面并报告失败；重新提交有效链接可去重继续合并。链接过期、角色不一致或服务器／时区冲突会停止剩余处理。空结果不创建空 UID 档案。

## 部署和状态边界

两个新任务模块各使用单 worker、有界队列和按用户隔离的内存状态；同一用户同类任务不能重复启动，请求间隔至少 1 秒。任务最多执行 30 分钟，链接最多 100,000 条／每池 5,000 页；签到批次最多 512 个结果。终态任务可在进程内查询，超过一天或队列清理后可能移除；服务重启不恢复任务状态。已完成签到与已写入数据库的记录保留，重试会先检查签到／按 ID 去重。

单部署仍只运行一个应用实例。更新源码后 `pnpm build`、`pnpm start`，Docker 重新构建镜像即可，原配置与数据库可继续使用。Nginx 子路径继续保留前缀转发；脚本下载也使用相同前缀，无需额外配置。

本轮验证以模拟上游为主，不调用真实签到或读取真实祈愿链接，不创建二维码。真实账号、渠道服／国际服与服务器网络下的成功情况需用户自验；需要官方安全验证时在 App 中处理，不承诺全部账号自动通过。

定向结果：相关 7 个测试文件 77 项通过，8 项真实 PostgreSQL 条件用例未运行；新模块为 3 项协议测试及 4 项接口集成测试，覆盖多角色／多账号、重复签到跳过、安全验证、POST 结果丢失的状态确认、所有者／管理员／CSRF 隔离，以及链接过期、固定上游、UID、合并、去重、取消和日志脱敏。前后端类型／构建、改动范围 lint 和 PowerShell 语法／合成缓存提取检查通过；图表分包体积提示保留。没有运行浏览器、Docker 或真实账号验收。
