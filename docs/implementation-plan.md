## 1. 执行方式

用户要求：先分配第一版每轮任务，之后一步一步生成代码，每轮 commit。

- 按下表顺序推进，默认一次工作轮次完成一个编号，不在同一轮自动连续实现全部第一版。
- 每轮先读当前状态和相关需求，完成该轮范围、必要验证和文档更新，再建立一个清晰的 commit。
- 默认 commit 消息采用下表建议的 Conventional Commit 风格；正文注明轮次、验证方式和仍未解决的限制。
- 每轮结束报告：本轮完成内容、验证结果、commit 短哈希、下一轮编号。未开始的事项不标成已完成。
- 每轮将状态表更新为已完成，并在本文 §7 写简短记录；同轮提交中一并保存。
- 通常一轮一个 commit；若单轮确实太大，可拆成 `Rxx-a / Rxx-b`，在执行前更新本表，每个独立部分各自验证和提交，不把几个轮次揉成一个大提交。
- 不为通过检查而提交明知失败的功能。依赖外部账号的验证受阻时，可提交独立、已验证的实现和明确的待实测说明，但该项验收仍保持待实测，不宣布首版全部完成。
- 普通可逆开发继续按已授权范围完成，不在每次运行测试、写文件或 commit 前重新询问。真实账号扫码、官方交互验证等本人操作在具体环节提示。
- commit 默认保存在本地 `main`，以远端已有提交为基础。用户要求的是每轮 commit；push、PR、远程发布与版本标签不作为自动执行步骤，需用户另外安排。
- 用户后续说“继续”时，先读取最新状态，再推进下一项未完成任务；如有待本人操作的项，保留其状态并推进不依赖它的下一项。

## 2. 第一版范围

以 [requirements.md](requirements.md) 为产品基线，保留其“确定需求 / 建议默认值 / 提案”区别。本计划将下列事项排入第一版：

1. 本地账号登录、非强制初始密码提醒、修改密码、退出。
2. 隐藏导航的管理员入口，创建普通账号、重置密码；首次启动生成并持久化管理员密码。
3. SQLite 默认与 PostgreSQL 可选，两种模式都提供和验证。
4. 原神 UIGF v4.0 / v4.1 / v4.2 导入导出、多 UID 档案、ID 去重及补历史。
5. 原版完整查询、分页、两项可选次数列、按星级名称颜色。
6. 原版完整物品分组统计、月度折线图和 Daily 热力图。
7. 米游社手动凭证、内置 App 扫码、国服原神手动刷新、本人 Token 查看与获取手册。端到端能力以真实验证结果为准。
8. 可部署的单服务构建、配置模板、备份说明和关键验收测试。

以下仍是建议默认值，不代表用户已经逐项选定：一个本地账号管理多个米游社账号和 UID；重置密码为 `12345678`；原神默认导出 v4.0；直接授权先验证国服官服。未收到更改时按这些建议落实，并在对应轮次说明。

首版不增加：自助注册、千星奇域、星铁正式功能、签到、角色 / 副本页面、UP 或欧非分析、新增资源消费统计。保留模块扩展边界即可，不预先实现这些功能。

旧 JSON 的历史迁移明确不做，不开发一次性转换器。直接参考用户提供且已通过 Schema 校验的 UIGF v4.1 文件；真实样例保留本地，自动化测试使用合成或匿名化数据。

祈愿链接导入已确认为必要功能，安排下一版，见 §5。第一版 R01–R16 的范围和顺序不因此增加或变更。

## 4. 每轮具体任务及验收

### R00：规划与仓库基础，本轮

范围：保留远端初始化历史，将已有需求、调研、架构和手册归档；确认新仓库名称；增加本计划、根 README 和必要忽略规则；建立文档 commit。

验收：本地链接有效；原用户 12 条需求均有对应；计划各轮有交付边界；真实样例 JSON、运行配置与凭证不进入提交。此轮不写应用代码。

### R01：工程骨架与基础运行

范围：采用 Node.js 24 LTS / TypeScript，建立 pnpm workspace、Fastify 服务、Vue 3 / Vite 前端及共享包入口；锁定稳定依赖；提供 dev、build、typecheck、lint、test 基础命令。服务端具备健康检查与静态前端服务，前端只有基础应用外壳。

验收：干净安装、类型检查和生产构建通过；开发模式可打开空应用；生产服务能返回健康状态与 SPA 页面。只验证基础启动，不为每个占位文件写镜像测试。

### R02：米游社最小验证工具

范围：实现开发者使用的最小 provider 探针，按已核对的 App 扫码流程创建 / 轮询票据；验证 SToken 身份、绑定角色、AuthKey 及少量祈愿分页。默认脱敏输出，不持久化长期凭证，不增加正式 UI、不自动刷新全量记录。

验收：模拟传输覆盖等待、确认、取消、过期、上游错误及缺字段；提供本人在目标网络完成扫码验证的可操作命令或步骤。真实验证有结果时记录脱敏结论；没有本人授权结果时标记“代码完成 / 待实测”，不能假报成功。

任务目的：先发现外部授权风险；SDK 和参考源码的行为差异在此轮固定为本项目适配规则。实际使用的 DS、设备上下文及当前接口参数只按现行公开实现核对，不把任意旧脚本当作可用凭据来源。

### R03：部署配置、双数据库、初始化

范围：实现 TOML / 环境变量配置、持久化目录、SQLite / PostgreSQL 驱动、独立 Schema 和迁移、Repository 基础；建立用户、会话、游戏档案、记录及任务所需数据结构。首次初始化生成并持久化管理员密码和凭证主密钥，重启不覆盖。

验收：SQLite 默认可启动；PostgreSQL 配置可启动；两库迁移可重复执行；唯一键、外键与 owner 范围有效。首次 / 再次启动、配置改密、缺失密钥报错有对应检查。不把修改数据库连接当作自动搬迁数据。

数据库的真实集成验证必须有两种数据库实例；环境未具备 PostgreSQL 时记录待验证，后续部署轮补齐，不能用 SQLite 结果代替。

### R04：本地认证与管理员 API

范围：实现普通用户登录、退出、当前用户、修改密码、初始密码状态；Session 与密码哈希；独立管理员认证及普通账号列表 / 创建 / 重置接口。没有公开注册 API，管理员业务范围只含创建和重置。

验收：初始密码为 `12345678`；提醒不强制；修改 / 重置会撤销原会话；普通用户不能使用管理员 API。管理员配置改密后旧管理会话失效。检查认证状态、Owner 越权、CSRF / Origin 与登录限速等真实权限边界。

### R05：登录、密码与管理页面

范围：实现 `/login`、个人改密、退出、初始密码非强制提醒及独立 `/admin` 页面；建立登录后的导航、用户与档案选择区域。管理员创建 / 重置账号页面不增加其他管理业务。

验收：管理员创建账号 → 普通账号初始密码登录 → 关闭提醒继续访问 → 修改密码 → 退出重新登录完整可走通；重置后提醒恢复。普通页面没有管理入口链接，直接访问管理 URL 仍需管理员认证。

### R06：抽卡领域逻辑与元数据

范围：实现长 ID 无损排序、原始类型 / 保底组映射、`301/400` 共享组、游戏时区转换、完整历史序号与五星间隔计算、缺口与未知元数据状态。建立可追溯的物品字典读取 / 更新边界与本地字典补全，不依赖真实用户数据。

验收：同秒多抽、超过 JS 安全整数的 ID、跨年、补入早期历史、首段不完整、未知星级、空档案等用固定样例验证。筛选或倒序后的单条记录次数必须仍与完整历史一致。所需原神物品数据有明确来源；未知新物品保留并提示，不猜 ID / 星级。

### R07：UIGF 导入导出后端

范围：固化已知三版 Schema 与专用类型，实现版本识别、多 UID 预览、选定档案事务合并、真实 ID 去重、冲突报告和标准导出。导出默认完整档案；未处理的游戏块明确跳过；合法缺省元数据按 R06 规则处理。

验收：v4.0/v4.1/v4.2 原神均可导入；重复文件新增为 0；后补历史能正确重算；无原神、错误版本、错误必填字段、含千星奇域的混合文件处理明确。两库导入结果一致；导出校验与空档案再导入后记录集合一致；文件中没有授权凭证。

### R08：数据管理与多 UID 页面

范围：实现 UIGF 上传 → 预览 → 选择档案 → 执行 → 结果流程，导出及当前 UID 切换；展示时间范围、元数据问题与跳过内容。接入离线档案，不要求米游社绑定。

验收：浏览器可完成实际上传、重复导入、查看多个 UID 与下载 UIGF；A/B 用户可独立保存相同 UID，切换本地用户不会残留前一用户的档案或缓存。旧内部 JSON 有明确的不支持提示。

### R09：完整查询功能

范围：一次完成记录查询 API 和表格页面，支持时间段、卡池多选、角色 / 武器多选、3–5 星多选、名称子串搜索、时间正倒序、可选总次数 / 保底内次数列、名称按星级着色及服务端分页。保留旧版日期快捷项与 20/50/100/200 分页大小。

验收：组合筛选、空结果、同秒顺序、页码边界、特殊搜索字符及跨用户查询均正确；改变筛选重置页码；筛选和分页不改变历史次数。用固定记录集核对接口与浏览器结果。

### R10：分析计算与接口

范围：实现物品 ID 聚合、角色两栏 / 武器三栏、数量排序数据；月度五条既有系列、缺月份补零；指定年份 / 卡池的日历统计，默认不选卡池为全部。只做原分析逻辑，不加入新的欧非或 UP 分析。

验收：对同一套固定记录能手算核对数量；跨年、闰年、无抽卡日、未知元数据与集录 / 新手计入总抽数行为正确；两库接口输出一致且受 owner / profile 限制。

### R11：三组统计页面

范围：实现角色 / 武器切换及星级分栏、月度 ECharts 折线图与图例 / 缩放、Daily 日历热力图。默认当前年、全部池，年份列表包括已有年份；全年无抽卡日期也能 hover 显示 0。

验收：默认筛选、切年份 / 卡池、hover 日期与次数、空档案、图表 resize 和 UID 切换有效；月 / 日 / 物品统计与 R10 对账。查询页筛选不会隐式影响分析页。

### R12：米游社凭证与账号后端

范围：实现当前用户的社区身份与游戏角色关系、手动 Token / Cookie 解析、验证能力状态、凭证加密、更新替换、本人 reveal / 复制 API 和解绑。已存在的离线档案绑定后补充 region，避免重复建档。

验收：缺少 SToken 不误报祈愿可用；有效新凭证验证后才替换旧值；解绑删除凭证并保留历史；跨 owner 的读取 / 验证 / reveal / 任务访问被拒绝。加密往返、重启解密、失效凭证及日志脱敏经过验证；不把未真实调用的上游能力标记为已验证。

### R13：内置 App 扫码后端

范围：把 R02 已核对链路接入正式认证与加密存储，实现一次性扫码会话、票据归属、有限轮询、确认后保存授权，以及取消 / 超时清理。区分 App 扫码与仅网页登录 Cookie 的能力。

验收：模拟传输验证全状态及跨用户取票、重复确认、过期 / 取消后的结果处理；真实本人扫码验证取得身份并能重新授权。若因上游变更不可用，保留清晰失败状态与手动导入能力，仍记录未通过的真实验收。

### R14：原神在线刷新任务

范围：实现手动创建刷新任务、验证角色归属、按池生成 / 使用 AuthKey、`end_id` 分页、ID 增量合并、有限退避、分池进度与失败重试；服务重启后的任务可重试；上游不再返回的本地历史不删除。

验收：重复刷新新增为 0、部分卡池失败、凭证失效、同档案并发锁、后台任务 owner、恢复重试和过期 AuthKey 路径有验证。用真实国服原神账号完成完整拉取后才记录支持范围；渠道服和国际服不继承官服验收标签。

### R15：米游社、Token 与刷新页面

范围：完成 `/accounts` 的扫码 / 手动导入、能力展示、绑定 UID、本人 Token 遮挡 / 查看 / 复制、更新凭证、解绑；加入刷新按钮与任务进度、结果及重试交互。将获取手册正式呈现在页内，并按已实测能力修正文案。

验收：浏览器能走完绑定 → 选 UID → 刷新 → 查询新增记录 → 导出；Token 默认接口和 DOM 不含完整明文，只有本人主动查看后呈现；失效、取消、空角色、部分完成都有可操作提示。管理员页面保持只含两项管理功能。

### R16：部署与第一版验收

范围：补齐 Dockerfile、SQLite 默认 Compose 与 PostgreSQL 配置示例、非容器运行说明、健康检查、持久化与升级步骤；说明配置、数据库、凭证主密钥的备份与恢复；检查全新部署和升级迁移。对照需求 §11 逐项确认完成状态，修复验收发现的问题。

验收：两种数据库各跑关键路径；重启保留管理员密码、用户、记录和 Token；使用合成数据跑 Playwright 关键流程；真实米游社链路列明测试环境和范围。凭证与个人记录未入库，README 与可运行行为一致。仍有待实测 / 未完成必做项时，文档明确列出，不宣布完整第一版已交付。

完成本轮后可以形成可部署提交，但默认不创建 Release、打远程标签或推送，等待用户安排。

## 6. 每轮验证与提交规则

### 6.1 验证按变化范围选择

- 文档轮：检查内容对应、相对链接、格式和提交范围，不运行无关应用测试。
