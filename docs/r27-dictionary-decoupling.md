# R27 实现：物品字典与原始记录解耦

更新：2026-11-04。对应 [前期调查](r27-dictionary-decoupling-research.md)。

## 使用变化

- 米游社刷新和祈愿链接导入遇到字典暂未收录的新物品时，继续保存该页全部有效记录并正常翻页，不再要求先匹配标准物品 ID。
- 查询中保留原始名称、类型、星级和时间；缺少标准 ID 时显示「物品 ID 待解析」。可以按已有字段筛选和分页。
- 物品分组可按原始名称、语言、类型和星级暂时归类。时间统计、热力图及可靠星级对应的统计照常计算，不要求先识别标准 ID。
- 更新字典后，已有原始记录和卡池名单自动使用新字典解析，无需重新获取祈愿记录／卡池；不批量改写原始抽卡事实。
- 管理员刷新／手动导入历史卡池时先保存原始英文角色标识或输入中已有的标准 ID，未知角色不再阻止整次保存。页面显示待解析引用数，字典刷新后重新读取卡池状态。

上游仍可能缺少名称、星级或类型；缺少哪个字段，就保留对应的不确定性。UID 不一致、非法时间／卡池、游标错误和真正的数据冲突继续报错，不会将无效响应当成成功数据。

## 数据保存与后续补全

`gacha_records.item_id` 现在允许 NULL。上游没有提供标准 ID 时保存 NULL，已有标准 ID 保持；不生成 `0`、负数或名称哈希充当游戏 ID。现有档案＋抽卡记录 ID 仍负责唯一性与去重。

原始 `metadata_json` 中的名称、语言、类型、星级、数量，以及记录 ID、时间、卡池类型继续保存。查询时按游戏对应的当前字典，用语言＋准确名称＋类型＋星级唯一匹配；歧义、缺少必要条件时保持未解析，不使用模糊名称猜测。为避免每条记录反复扫描字典，名称查询索引在每个字典实例建立时生成。

已有存储 ID 优先，字典更新不会替换它。旧版本从字典推断并已经存下来的 ID 也保留，不猜测其历史来源。字典更新可能使待解析分组归并、某些分析变得完整，但不会新增／删除抽卡记录或更改原始名称和时间。

导入同一抽卡 ID 的 UIGF 可以补充原先缺失的标准 ID，按一次丰富更新处理，不新增重复抽卡。两个可确定的 ID 互相矛盾或时间／卡池等事实不一致时仍按冲突处理；页事务与检查点保持一致。

用户上传记录带来的 ID 仅丰富本人记录，不写入全局物品字典。

## 历史卡池与欧非分析

在线及 JS 手动导入保留 `featured` 中的原始英文角色标识。已有 `itemIds` 的旧版快照继续兼容，输入中合法但尚未收录的 ID 也可保存。

读取时从原始名单生成当前字典下的有效名单及未解析数量，原始快照不改写。卡池版本表示源文件内容，字典版本表示解析环境；现有分析一致性检查继续同时使用两者。

不能判断时显示未知，避免污染小保底概率、UP 成本及连续次数：

- 记录缺标准 ID，无法与当期名单对应时，相关 UP 样本排除并中断连续状态。
- 窗口内有未解析 UP 成员时，未命中已识别成员不直接判为歪；命中明确已知的 UP 仍可判定。
- 完整五星间隔等只依赖可靠星级和历史边界的指标继续计算。
- 卡池格式、时间和覆盖范围检查继续执行，网络失败保留旧版。原有直连失败后询问代理的交互保持。

## 标准导出与无损原始备份

数据管理增加「下载无损原始备份」。该文件可使用同一个导入入口预览、选择 UID 并恢复，继续经过本人隔离、签名预览、去重和冲突检查。

原始备份格式为 `GachaRecordsViewer.raw`、版本 1，文件名以 `GachaRecordsViewer_raw_` 开头。它保留当前档案全部已保存的抽卡原文和 NULL ID，不导出字典派生的显示名、临时分组键或推断 ID，不含授权 Token、应用配置及账号绑定。它是抽卡记录备份，不代替部署数据库备份；恢复仍受单次 16 MiB、32 个档案、100,000 条记录限制。

UIGF v4.0／v4.1／v4.2 导出时，已有 ID 和能够由当前字典唯一解析的 ID 都可输出。有未解析 ID 时返回 `ITEM_IDS_PENDING`，页面提示先下载原始备份或等待字典补全；不会静默遗漏记录，也不将 NULL／本地临时键写进标准 ID。外部 UIGF 输入继续按原有标准校验，不借原始备份功能支持旧工具私有 JSON。

API 模拟：

| 格式 | 行为 |
| --- | --- |
| 祈愿链接／米游社 | 保留全部记录；待解析项的 `item_id` 为空字符串，名称、星级等已知字段保留。第三方应用需自行识别。 |
| UIGF | 只有全部 ID 可确定时创建；否则明确提示。生成失败不销毁已有的有效链接。 |

新增 `GET /api/raw-backup/export/:profileId`，沿用用户会话、本人档案和站点子路径保护。原 `POST /api/uigf/preview`、`POST /api/uigf/import` 同时识别标准 UIGF 和本应用原始备份；预览中后者显示为「无损原始备份」。

## 部署升级

这次包含数据库迁移 **0003**，升级前按现有流程备份部署数据库。更新源码、构建并重启即可自动迁移，不新增配置、依赖或环境变量。

- SQLite：事务内重建抽卡记录表，复制原字段，仅放宽 item_id 约束，保留主键、索引和外键。
- PostgreSQL：对 item_id 执行 `DROP NOT NULL`，不重建历史内容。
- 已有账号、凭证、绑定、字典、记录和卡池缓存继续保留。旧版仅含 itemIds 的卡池快照仍可加载。
- 产生 NULL ID 后，旧版程序对该字段的非空假设不再成立；需要回滚时应同时恢复对应的升级前数据库备份。

## 验证

受影响模块 17 个测试文件通过，共 **85 项通过、19 项外部数据库条件用例跳过**。覆盖：

- 新物品在米游社／祈愿链接中整页保存、翻页、重复刷新去重及用户隔离。
- 缺 ID 时查询／基础统计／API 模拟可用，标准导出明确拒绝、原始备份可往返。
- 字典更新后已有记录和卡池直接解析，数据库原始行不变；后续 UIGF 仅丰富原行。
- 歧义保持未知，已存 ID 不被替换，部分未知 UP 不误判为歪。
- 旧 SQLite 升级后的原始行、设置、索引与外键保留；重复迁移稳定。
- 既有核心分析、UIGF、查询、临时 API、签到及导入行为回归。
